# Phase 4: E2E 테스트 (Playwright)

## 1. 개요
* 모든 단위 기능 및 UI 통합이 완료된 후 Playwright를 사용하여 사용자 관점에서의 전체 흐름을 테스트.

## 2. 주요 테스트 시나리오
* **시나리오 A (메인 랜딩 및 대시보드 렌더링)**:
  * 초기 페이크 데이터가 대시보드의 각 차트/표에 정상적으로 렌더링되는지 확인.
* **시나리오 B (기타 생산량 입력 흐름)**:
  1. 입력 폼에서 '기타 생산량' 선택 후 수치 입력.
  2. 폼 제출 후 로딩 상태 및 에러 미발생 대기.
  3. 대시보드의 Scope 1, 2 및 PCF 데이터가 예상치만큼 갱신되었는지 확인.
  4. Post 이력 목록에 "Kender 2026-05 통합 배출 이력" 항목이 추가 또는 업데이트되었는지 확인.
* **시나리오 C (부품 수입 입력 흐름)**:
  1. 입력 폼에서 '픽업 수입' 선택 후 개수 입력.
  2. 폼 제출 후, 대시보드에서 Kender 본사가 아닌 인도네시아 픽업회사, 인도네시아 수입회사, 국내배송회사 총 3곳의 배출량이 각각 갱신되었는지 확인.
  3. 모든 Scope가 3으로 정상 분류되었는지 확인.
  4. Post 이력 목록에 위 3곳의 회사별로 **각각 별개의 Post 객체 3개**가 성공적으로 생성 및 노출되었는지 확인.
* **시나리오 D (에러 핸들링)**:
  * 페이크 API의 `maybeFail()` 로직에 의해 랜덤하게 실패할 경우, UI에 올바른 에러 메시지(Toast 등)가 노출되는지 테스트.
* **시나리오 E (오입력 보정을 위한 마이너스 차감 흐름)**:
  1. 폼에 양수 값을 입력하여 배출량을 상승시킴.
  2. 동일한 배출 항목에 마이너스(-) 값을 입력하고 제출.
  3. 대시보드에서 합산된 배출량 총계가 마이너스 값만큼 정확히 차감되었는지 검증.
