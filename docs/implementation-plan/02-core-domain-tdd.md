# Phase 2: 핵심 도메인 로직 TDD (Core Domain TDD)

## 1. 개요
* 탄소 배출량 자동 계산 및 Company 객체로 분산 할당하는 핵심 비즈니스 로직을 TDD 방식으로 구현함.
* 외부 API나 UI에 의존하지 않는 순수 함수 모듈(`lib/emissions-calculator.ts` 등)로 분리하여 테스트 가능성(Testability) 극대화.

## 2. 단위 테스트 작성 (Red) -> 구현 (Green) -> 리팩토링
각 입력 시나리오에 대해 Vitest 테스트를 먼저 작성.

### 2.1. 기타 생산량 입력
* **테스트**: 10대 생산 입력 시 Kender 객체에 Scope 1(2단계), Scope 2(2단계), Scope 3(4, 5단계) 배출량이 정확히 산정되어 `emissions`에 푸시되는지 확인. **중복 시 합산 로직은 `yearMonth`, `source`, `scope`, `pcfStage`가 모두 완전히 일치할 경우에만 작동하는지 엄격히 검증**.
* **구현**: 배출량 산정에 필요한 배출계수는 기획된 실데이터가 없으므로 가상의 상수 값들을 선언(예: `lib/constants.ts`)하여 활용하는 계산 로직 및 Post 생성 로직 작성. 재고 변동성을 배제한 PCF 단위 산출을 위해 '표준 부품 비율(BOM)' 상수 데이터도 함께 선언 및 적용.

### 2.2. 기타 배송 총 거리 입력
* **테스트**: 소비자 배송 거리 입력 시 국내배송회사 객체에 Scope 3(3단계) 배출량이 올바르게 추가되는지 확인.
* **구현**: 거리 기반 배출량 산정 로직 구현.

### 2.3. 수입 개수 입력 (픽업, 기타줄)
* **테스트**: 부품 수입 시나리오에서 공급사(1단계), 수입회사(3단계), 국내배송회사(3단계) 3곳으로 배출량이 분산 합산되는지 확인. (Scope는 모두 3으로 Kender 기준 치환됨 검증)
* **구현**: 각 단계별 수입 배출량 분산 할당 로직 작성.

### 2.4. 오입력 마이너스(-) 차감 (Rollback) 입력
* **테스트**: 이전에 입력된 수치에 대한 보정을 위해 마이너스 값을 입력했을 때, 배출계수와 연산되어 전체 배출량 수치가 정확히 차감(감소)되어 합산되는지 확인.
* **구현**: 음수(-) 입력값도 동일한 분산 계산 파이프라인을 통과하여 `emissions`에 안전하게 병합될 수 있도록 허용 처리.
