# ADR 0001: Supabase와 Drizzle ORM을 이용한 실제 API 전환 및 관계형 데이터 모델링

## 상태
승인됨

## 맥락
기존 탄소 배출량 관리 플랫폼의 프로토타입은 메모리 상의 임시 데이터베이스(`src/lib/fake-db.ts`)를 사용하여 탄소 배출 데이터를 읽고 썼습니다. 서비스의 신뢰성과 데이터 정속성을 보장하기 위해 실제 데이터베이스인 Supabase(PostgreSQL)를 연동하고 Drizzle ORM을 사용하여 실제 API 코드로 전환해야 합니다.

이 과정에서 메모리 구조의 `Company` 객체가 가지고 있던 중첩된 `emissions` 배열을 실제 관계형 데이터베이스로 마이그레이션할 때의 구조 설계, 대용량 및 빈번한 조회 환경에서의 배출량 누적 방식, 그리고 데이터의 일관성을 유지하기 위한 트랜잭션 범위에 대한 결정이 필요합니다.

## 결정 사항

### 1. 관계형 스키마 설계 (1:N 테이블 분리)
`companies`와 `emissions`를 JSONB 형식으로 묶어 저장하지 않고, 외래키(`company_id`)로 연결된 1:N 관계의 독립된 테이블로 분리합니다.
* `countries`: 2글자 국가코드를 기본키로 하며 국가 정보를 관리합니다.
* `companies`: 회사의 기본 인적 사항을 관리하며 `countries` 테이블을 참조합니다.
* `emissions`: 개별 배출량 항목을 저장하며 `companies` 테이블을 참조합니다.
* `posts`: 회사별 배출 이력 피드 글을 관리하며 `companies` 테이블을 참조합니다.

### 2. 복합 유니크 제약조건 기반의 Upsert 처리
배출 계산기 실행 결과로 나오는 대량의 누적 데이터를 효율적으로 집계하기 위해, `emissions` 테이블에 `(company_id, year_month, source, scope, pcf_stage)` 5개 컬럼의 복합 유니크 제약조건을 정의합니다. 데이터 삽입 시 충돌이 발생할 경우, 기존 배출값에 새로운 배출량을 더하는 방식으로 업데이트(ON CONFLICT DO UPDATE)를 수행하여 데이터 중복을 방지하고 쿼리 속도를 최적화합니다.

### 3. 단일 트랜잭션(Transaction) 내에서 API 쓰기 처리
`submitEmissions`와 같이 배출량 정보를 저장하고 이에 해당하는 피드 글(`Post`)을 작성/갱신하는 쓰기 작업들은 데이터베이스 수준의 단일 트랜잭션으로 묶어 원자성을 보장합니다.

### 4. 독립형 시드 스크립트 구축
초기 데이터 적재를 위해 Next.js 구동 시점에 동적으로 채우는 방식 대신, 별도의 명령어로 실행할 수 있는 독립형 시드 스크립트(`src/db/seed.ts`)를 작성하고 `tsx` 실행기를 활용합니다.

## 결과 및 트레이드오프
* **장점**: 대시보드 통계 조회 시 Join과 집계 쿼리가 데이터베이스 엔진 수준에서 수행되므로 애플리케이션의 메모리 부하가 낮아지고 성능이 크게 향상됩니다. 또한 트랜잭션 보장을 통해 데이터 불일치 버그를 근본적으로 예방할 수 있습니다.
* **단점**: 기존 단일 객체 지향적이었던 프론트엔드와 메모리 기반 API 코드보다 Drizzle 스키마 정의 및 트랜잭션 코드 작성의 난이도가 소폭 상승합니다.
