# 탄소배출관리 플랫폼 브레인스토밍

## 솔루션 개요
기업 고객이 원소재, 전기, 운송 데이터를 입력하면 제품별 탄소 발자국(PCF)을 자동으로 계산해 주는 플랫폼.

## 가정 (Assumptions)

### 1. 솔루션 대상 기업 (시스템 내 고정된 6개 Company 객체)
1. **Kender (자사)**: 본사 및 자체 공장 (Scope 1, 2 발생, 기타 조립 및 판매)
2. **중국기타줄회사**: 기타줄 생산 공급사
3. **인도네시아픽업회사**: 픽업 생산 공급사
4. **중국수입회사**: 중국산 기타줄 수입 운송 담당 (운송 시 배출량 계산)
5. **인도네시아수입회사**: 인도네시아산 픽업 수입 운송 담당 (운송 시 배출량 계산)
6. **국내배송회사**: 수입된 부품을 자사 공장으로 운송하거나, 완성된 기타를 소비자에게 배송하는 역할

### 2. 온실가스 배출량 계산 로직
* **공급원별 산정 방법 적용 가능성**: 중국과 인도네시아의 협력회사로부터 Cradle-to-gate 배출계수를 제공받을 수 있다고 가정함. 따라서 `제품 사용량 × 배출계수`로 Scope 3 배출량을 산정할 수 있음.
* **전 과정 평가 (LCA) 범위**: 기타 조립/생산 단계의 데이터뿐만 아니라, 유통 및 물류, 제품 사용, 제품 폐기 단계의 데이터도 확보할 수 있다고 가정함. 결과적으로 생산 단계까지의 **Cradle to Gate PCF** 외에도, 생애주기 전체를 포괄하는 **Cradle to Grave PCF**까지 계산할 수 있음.
* **전기 사용량 배출계수 (Scope 2)**: 국가 단위의 평균 전력망 배출계수를 일괄적으로 적용하여 계산함.
* **제품 사용 단계 (Scope 3) 산정 기준**: 제품 수명, 일평균 사용 시간, 소비 전력 등에 대한 표준 가정치가 플랫폼 내에 미리 정의되어 있으며, 이를 바탕으로 배출량을 산정함.

## 소프트웨어 기능 정리

### 1. 대시보드 (전체 온실가스 배출량 및 PCF)
대시보드에서는 다음 항목들에 대해 **전체 온실가스 배출량**과 **제품 단위당 탄소 발자국(PCF)**을 각각 나누어 조회 및 분석할 수 있어야 함.
* **Scope 별 분석**: Scope 1, 2, 3 기준 (전체 배출량 및 PCF)
* **회사별 분석**: 자사(Kender 본사), 중국 공장, 인도네시아 공장 (전체 배출량 및 PCF)
* **측정 범위별 분석**: Cradle to Gate, Cradle to Grave (전체 배출량 및 PCF)
* **생애 주기별 분석**: 1단계(원자재) ~ 5단계(제품 폐기) (전체 배출량 및 PCF)

### 2. PCF 자동 계산

#### 입력 종류
1. 기타 생산량
2. 기타 배송 총 거리
3. 픽업 수입 개수
4. 기타줄 수입 개수

#### 입력 시 공통 동작
1. 사용자가 항목 선택 후 수량 혹은 거리를 입력함.
2. 각 항목별 자체 알고리즘(배출계수, 표준 가정치 등)을 기반으로 배출량을 계산함.
3. 계산된 배출량으로 `ExtendedGhgEmission` (기존 타입에 `scope`, `pcfStage` 확장) 객체를 생성하여, 해당 `Company`의 `emissions` 배열에 추가(`push`)함.
   * *단, 이미 해당 회사 및 해당 월(`yearMonth`)에 배출원(`source`)까지 완전히 동일한 `ExtendedGhgEmission`이 존재하는 경우에만 기존 객체의 `emissions` 값에 누적하여 더함.*
4. `Post` 객체를 생성하여 데이터 입력 이력을 기록함.
   * `title`: 처음부터 "Kender 2026-05 통합 배출 이력"과 같이 포괄적인 제목을 사용함.
   * `content` 예시: "픽업 20개 수입, 000tCO2e 배출"
   * *단, 이미 해당 회사 및 해당 월에 관련된 `Post`가 존재하는 경우, 기존 `title`은 유지하고 `content`에 줄 바꿈을 추가하여 새로운 이력 문자열을 덧붙임.*

#### 개별 입력 항목 상세 (내부 복잡한 동작 예시)
*사용자는 간편하게 하나의 수치를 입력하지만, 소프트웨어 내부에서는 Kender(자사) 기준으로 여러 회사와 Scope에 걸쳐 복잡하게 동작함.*
*(중요)* 협력사/공급사 입장에서는 Scope 1, 2에 해당할지라도, 플랫폼 내 모든 PCF 단계와 Scope 분류는 항상 자사인 **Kender 기준**으로 치환되어 기록됨.

1. **기타 생산량 입력** (예: 기타 10대 생산)
   * 생산 시 사용한 화석연료 배출량 -> **Scope 1, PCF 2단계** (Kender 배출량에 추가)
   * 생산 시 사용한 전력 배출량 -> **Scope 2, PCF 2단계** (Kender 배출량에 추가)
   * 사용자 제품 사용 시 배출량 -> **Scope 3, PCF 4단계** (Kender 배출량에 추가)
   * 제품 폐기 시 배출량 -> **Scope 3, PCF 5단계** (Kender 배출량에 추가)
   * Kender 객체에 위 배출량들을 합산/분류하여 추가하고 Post 이력 업데이트.

2. **기타 배송 총 거리 입력** (예: 소비자 배송 100km)
   * 완성된 기타를 배송 대행을 통해 소비자에게 전달 시 발생하는 배출량.
   * 배송 배출량 산정 -> **Scope 3, PCF 3단계** (국내배송회사 배출량에 추가)
   * 국내배송회사 객체에 배출량 추가하고 Post 이력 업데이트.

3. **픽업 수입 개수 입력** (예: 픽업 10개 수입)
   * 픽업 부품 생산 배출량 산정 -> **Scope 3, PCF 1단계** (인도네시아픽업회사 배출량에 추가 및 Post 업데이트)
   * 인도네시아 -> 한국 운송 배출량 산정 -> **Scope 3, PCF 3단계** (인도네시아수입회사 배출량에 추가 및 Post 업데이트)
   * 한국 항구 -> Kender 공장 국내 배송 배출량 산정 -> **Scope 3, PCF 3단계** (국내배송회사 배출량에 추가 및 Post 업데이트)

4. **기타줄 수입 개수 입력** (예: 기타줄 10세트 수입)
   * 기타줄 부품 생산 배출량 산정 -> **Scope 3, PCF 1단계** (중국기타줄회사 배출량에 추가 및 Post 업데이트)
   * 중국 -> 한국 운송 배출량 산정 -> **Scope 3, PCF 3단계** (중국수입회사 배출량에 추가 및 Post 업데이트)
   * 한국 항구 -> Kender 공장 국내 배송 배출량 산정 -> **Scope 3, PCF 3단계** (국내배송회사 배출량에 추가 및 Post 업데이트)
